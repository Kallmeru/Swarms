SWARMS: core/ reference
=======================
Taint tracking - Capability attenuation - Policy enforcement - Agent runtime
- Structured event logging

core/ is the security kernel: the only part of the project that decides
whether a privileged action happens. Around 600 lines of pure Python, zero
dependencies (the optional LLM client is the one exception and is never on
the enforcement path), fully deterministic.

  core/
  ├── taint.py        labels, propagation, provenance chains
  ├── capability.py   granted authority, attenuation, per-run scope
  ├── policy.py       the two rules, and a reason for every verdict
  ├── runtime.py      the wrapper each agent runs inside
  ├── logger.py       JSON-lines events, the format everything else reads
  └── llm_client.py   optional real-model backend (Groq / OpenAI / Gemini)

The wire format and the full integration contract are in
docs/swarms-integration-schema.md. That file is the one to read before
changing anything here.


1. Taint model (taint.py)
-------------------------
TaintLabel      TRUSTED / UNTRUSTED
TaintedValue    a value, its label, and the provenance chain that earned it
  .derive(v, tag)   compute a new value; keeps the label, extends the chain.
                    The single operation agents should use, so propagation is
                    a property of the type rather than of every caller
                    remembering to do it.
  .trusted() / .untrusted()   labeled constructors
propagate_label(*labels)      variadic join: one untrusted input taints the
                              result. Variadic because folding pairwise in
                              every caller is where a label gets dropped.
combine(*values)              merge N values, label and provenance included
wrap_raw(value, agent)        an agent's unlabeled return is UNTRUSTED. Fails
                              closed: no benefit of the doubt.

There is no path from UNTRUSTED back to TRUSTED. That absence is the design;
any such path is exactly what prompt injection attacks.


2. Capability model (capability.py)
-----------------------------------
Capability      frozen dataclass: can_email / can_execute / can_write_file,
                with a set-like view (.granted, .of(), .intersect(), .allows())
                Frozen so a shared object cannot be mutated by one handoff and
                silently stop applying everywhere else.
attenuate(cap)  authority as it survives a boundary: what the agent was
                granted, intersected with what this run's task authorizes.
                Monotonically shrinking. With the shield off, unchanged, which
                is the vulnerable baseline where authority rides the data.
run_policy(shield=, authority=)
                context manager scoping both settings, restored exactly even
                if the body raises.

Run state is contextvars, not module globals. Not a style preference: the API
server runs many pipelines at once, and a global would let one request's
shield setting leak into another's, silently disabling the defense under load.

allows() denies unknown actions. New verbs arrive denied, not permitted.


3. Policy engine (policy.py)
----------------------------
authorize(action, args, capability) -> Decision(allowed, reason,
                                                offending_arg, offending_span)

  1. shield off        -> allow (baseline)
  2. unknown action    -> deny
  3. authority         -> agent holds it AND the task authorized it
  4. grounding         -> every CONTROL argument must be TRUSTED

CONTROL_ARGS names, per action, the arguments that steer what the action does
to the world: recipient, command, path. Everything else is a data argument and
may carry untrusted content. An email body quoting the poisoned document is
ordinary work and goes through; an email whose recipient came from that
document does not. That split is the difference between a defense and an off
switch, and it is why the benchmark reports a false-positive rate.

Taint detection recurses through dicts, lists, tuples and sets: arguments
nest, and a top-level-only check misses to=[ok@x, attacker@y].

Decision is a NamedTuple, so it still unpacks as the 4-tuple older code
destructures.


4. Agent runtime (runtime.py)
-----------------------------
AgentRuntime(agent_fn, capability, agent_name, tools=None)
  .run(value)              label in, label out, log both ends
  .handoff(next, value)    data crosses, authority does not: the receiver's
                           capability is re-derived at the boundary rather
                           than carried
  .privileged_action(a, args)
                           policy check first, tool lookup second. A denied
                           action never touches the tool, so there is no
                           window where the side effect has started and the
                           check has not finished.

The agent function is ordinary code (or an LLM call) and is trusted to do none
of this. Enforcement cannot be talked out of by content an agent read, because
the content never reaches the enforcement path, only the data path.


5. Event logger (logger.py)
---------------------------
run_context(run_id, persist=False)   scope a run; .events is the trace
log_event(type, data)                one JSON object, envelope documented in
                                     docs/swarms-integration-schema.md
current_events()                     a copy, not the live list

In memory by default; writes runs/<run_id>/events.jsonl only when a run asks
to persist, because a server writing a file per request grows without bound
for output nobody reads. Debug-level logging, never print(): a library that
writes to stdout unasked corrupts any caller emitting JSON or CSV on the same
stream.

python -m pytest tests -q            the suite (core, pipeline, API)
python Demo.py                       end-to-end, no server
python -m benchmark.run_benchmark --strict
                                     non-zero exit if any attack got through
                                     or any legitimate task was refused
